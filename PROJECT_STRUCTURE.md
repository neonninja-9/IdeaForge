# IdeaForge - Project Structure & Architecture

This document outlines the project structure and architectural patterns used in the **IdeaForge** application to help other agents navigate and understand the codebase.

## High-Level Architecture

IdeaForge is a full-stack web application consisting of:
- **Frontend**: React (v19) single-page application built with Vite and Tailwind CSS v4, using TypeScript.
- **Backend**: Node.js / Express REST API using MongoDB via Mongoose.

The project uses a monorepo-style setup with two main directories: `frontend` and `backend`. They can be run concurrently from the root using `npm run dev`.

---

## 1. Frontend (`/frontend`)

The frontend is a React SPA using React Router for navigation and Context API for state management. It communicates with the backend via a centralized API client.

### Key Directories

- **`src/pages/`**: Top-level route components. 
  - Notable pages: `LoginPage.tsx`, `RegisterPage.tsx`, `DashboardPage.tsx`, `IdeasFeedPage.tsx` (Explore), `IdeaDetailPage.tsx`, `SubmitIdeaPage.tsx`, `UserProfilePage.tsx`.
- **`src/components/`**: Reusable UI components.
  - Notable components: `Navbar.tsx`, `Footer.tsx`, `Hero.tsx`, `CTABanner.tsx`, `IdeaCard.tsx`, `AuthDoodles.tsx` (animations).
- **`src/context/`**: Global state management.
  - `AuthContext.tsx`: Manages user session, JWT access token, and login/logout functions.
- **`src/hooks/`**: Custom React hooks.
  - `useAuth.ts`: Hook to consume the `AuthContext`.
- **`src/services/`**: API communication layer. Maps to backend REST endpoints.
  - `apiClient.ts`: Central fetch wrapper that injects the JWT bearer token into headers.
  - `authService.ts`: Login, register, refresh, logout API calls.
  - `ideaService.ts`: Idea fetching, creation, and dashboard endpoints.
  - Others: `categoryService.ts`, `commentService.ts`, `tagService.ts`, `voteService.ts`.
- **`src/types/`**: TypeScript interfaces and types.
  - `auth.types.ts`: User and auth response types.
  - `idea.types.ts`: Idea, category, tag, and comment types.
- **`stitch_html/`**: Static HTML mockups (likely generated by a design tool before React implementation).

### Routing (`src/App.tsx`)
Routing is handled by `react-router-dom`. 
- **Landing Layout**: General public pages (Home) use a shared layout wrapping the content with `Navbar` and `Footer`.
- **Platform Pages**: App pages (Dashboard, Explore, Submit Idea) handle their own navigation layout and are rendered directly.
- **Auth Pages**: Login and Register are rendered as full-page immersive experiences without standard navbars.

## 2. Backend (`/backend`)

The backend is an Express.js server connected to MongoDB. It follows a layered architecture (Controller-Service-Repository pattern).

### Key Directories

- **`src/routes/v1/`**: Express route definitions.
  - Endpoints are split by resource: `auth.routes.js`, `idea.routes.js`, `category.routes.js`, `comment.routes.js`, `tag.routes.js`, `vote.routes.js`.
  - Mounted centrally in `index.js`.
- **`src/controllers/`**: Handle HTTP request/response logic and map to services.
- **`src/services/`**: Core business logic and orchestration.
- **`src/repositories/`**: Data access layer interacting with Mongoose models.
- **`src/middlewares/`**: Express middlewares for auth checking, validation, and error handling.
- **`src/config/`** / **`src/utils/`**: Configuration and utility functions.
- **`src/validators/`** / **`src/transformers/`**: Request validation and response formatting.
- **`models/`**: (Root level or inside src) Mongoose schema definitions (`user.js`, `idea.js`, etc.).

### Database & Environment
- **Database**: MongoDB Atlas (Connection string provided via `.env`).
- **Initialization**: `init.js` and `seed.js` exist in the backend root for seeding the database with sample data.
- **Entry point**: `server.js` starts the Express server, connects to DB, and handles global errors.
- **Environment**: Requires `.env` with `MONGODB_URI` to run successfully.

---

## Integration Details

- **Authentication**: JWT-based. The backend sets an `httpOnly` cookie for refresh tokens and returns a short-lived access token. The frontend `AuthContext` periodically refreshes the token on mount and syncs it with `apiClient.ts` for subsequent requests.
- **Start Command**: `npm run dev` at the workspace root utilizes `concurrently` to launch the Vite frontend and Node backend simultaneously.
